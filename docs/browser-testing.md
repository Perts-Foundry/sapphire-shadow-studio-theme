# Browser testing

Companion to the Browser testing section of the root `CLAUDE.md`, which holds the opt-in rule (do not auto-open preview or storefront URLs) and the screenshot check. These are the mechanics that bind only while driving the chrome-devtools MCP against the storefront, a PR preview theme, or Shopify admin.

- **The storefront is public** (verified 2026-09-08 against the custom domain), so anonymous requests reach real pages and the password-bypass step below is history for the LIVE theme. What did not change is the **preview** theme: a `?preview_theme_id=` link is still not a public URL, so reaching an unpublished draft theme still means opening the store's admin themes page (`https://admin.shopify.com/store/sapphire-shadow-studio/themes`), opening the draft theme's "more theme actions" menu, and using its **Preview** link. That link carries a `key=` param that sets the preview cookie for the whole browser session; curl does not pick it up. If a storefront request ever comes back as a 401 or a password page again, the store has been re-locked in Admin, and that is the finding rather than a fault in the request.
- **hCaptcha blocks automated form submits.** Shopify's invisible hCaptcha will not complete for storefront form submissions from the automation-flagged MCP browser, so full contact-form round trips must be verified manually.
- **Shopify admin login loops in the MCP browser.** accounts.shopify.com silently rejects the chrome-devtools MCP's automation-flagged Chrome, looping "Continue with email" forever. Workaround: kill the MCP-launched Chrome, relaunch the same binary manually with the same `--user-data-dir` (`~/.cache/chrome-devtools-mcp/chrome-profile`) but no automation flags, log in there, then close it; the next MCP call relaunches the browser and the session cookies carry over until the profile's login expires.
